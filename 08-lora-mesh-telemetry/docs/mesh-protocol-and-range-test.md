# LoRa Mesh Packet Protocol & Spreading Factor Range Analysis — 08 LoRa Mesh Telemetry

This document specifies the pipe-delimited mesh framing protocol implemented across [`lora_mesh_node.ino`](../src/lora_mesh_node/lora_mesh_node.ino) and [`lora_mesh_gateway.ino`](../src/lora_mesh_gateway/lora_mesh_gateway.ino), analyzes Chirp Spread Spectrum (CSS) **Spreading Factor (`SF7`–`SF12`)** engineering trade-offs, and provides multi-hop UART trace logs.

---

## 1. LoRa Mesh Packet Frame Specification

Each mesh frame is serialized as a compact, single-packet ASCII structure delimited by pipe characters (`|`) to remain well below the 255-byte hardware FIFO buffer limit of the Semtech SX127x while remaining human-readable during UART debugging:

```text
MSG_ID | SRC_ID | DST_ID | VIA_ID | HOP_COUNT | MAX_HOPS | JSON_PAYLOAD
```

| Header Field | C++ Type | Example Value | Protocol Function |
| :--- | :--- | :--- | :--- |
| `MSG_ID` | `uint16_t` | `104` | Monotonically increasing sequence number generated by the origin node (`srcId`) |
| `SRC_ID` | `uint8_t` | `1` (`0x01`) | Originating sensor node address |
| `DST_ID` | `uint8_t` | `0` (`0x00`) | Final destination address (`0x00` = Border Gateway) |
| `VIA_ID` | `uint8_t` | `2` (`0x02`) | Address of the last repeater node that transmitted this frame |
| `HOP_COUNT` | `uint8_t` | `1` | Cumulative number of hops traversed so far |
| `MAX_HOPS` | `uint8_t` | `3` | Maximum hop limit (*Time-To-Live* / TTL) before packet expiration |
| `JSON_PAYLOAD` | `String` | `{"t":27.4,"h":78.5,"dist":120.0,"water":180.0,"alert":false}` | Application-layer environmental & hydrological telemetry |

### Loop Prevention via Deduplication Ring Buffer (`seenBuffer[24]`)
Flooding-based wireless mesh networks are vulnerable to infinite ping-pong re-broadcast loops (*broadcast storms*). Every node and gateway maintains a 24-entry circular buffer `seenBuffer` storing `(srcId, msgId)` tuples:
1. Upon demodulating a valid frame, the node searches `seenBuffer` for a matching `(pkt.srcId, pkt.msgId)` pair.
2. If **present**, the packet is immediately **dropped (`DROP`)** without re-transmission.
3. If **absent**, the tuple `(srcId, msgId)` is inserted into `seenBuffer`. If `hopCount < maxHops` and `dstId != NODE_ID`, the repeater increments `hopCount`, sets `viaId = NODE_ID`, delays for a randomized CSMA backoff window (`50–250 ms` to avoid RF collisions between neighboring repeaters), and re-transmits the frame.

## 2. Chirp Spread Spectrum (CSS) Spreading Factor Trade-Offs (`SF7`–`SF12`)

In LoRa modulation, the **Spreading Factor ($\text{SF} \in \{7..12\}$)** defines the number of chips per symbol ($2^{\text{SF}}$), governing the fundamental trade-off between **Demodulation Sensitivity (Range)** and **Time-on-Air (Spectral Occupancy & Battery Drain)**:

| Spreading Factor | Nominal Bitrate (`BW = 125 kHz`, `CR = 4/5`) | Receiver Sensitivity | Demodulator SNR Floor | Time-on-Air (64-Byte Frame) | Recommended Deployment Scenario |
| :---: | :---: | :---: | :---: | :---: | :--- |
| **`SF7`** | ~5,470 bps | `-123 dBm` | `-7.5 dB` | ~118 ms | Short-range (< 1.5 km), high density, ultra-low battery consumption |
| **`SF8`** | ~3,125 bps | `-126 dBm` | `-10.0 dB` | ~215 ms | Medium-range suburban / campus telemetry |
| **`SF9` (Default)** | ~1,760 bps | `-129 dBm` | `-12.5 dB` | ~390 ms | **Optimal balance** for multi-hop mesh relaying |
| **`SF10`** | ~980 bps | `-132 dBm` | `-15.0 dB` | ~698 ms | Dense forest canopy / hilly terrain (3–6 km per hop) |
| **`SF12`** | ~250 bps | `-137 dBm` | `-20.0 dB` | ~2,465 ms | Extreme range (> 10 km LoS); high collision probability in mesh |
